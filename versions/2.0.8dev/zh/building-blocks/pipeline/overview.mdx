---
title: "概述"
description: "按照固化逻辑运行多智能体，并向外提供统一接口"
---

流水线（Pipeline）是多智能体的一种组合方式：智能体之间的运行顺序与流转条件由开发者预先确定，运行过程中不再改变；对外则收敛成与单个智能体相同的形态 —— 递入输入，流式取回事件。

它承担三件事：

| 职责 | 说明 |
|------|------|
| 固化运行逻辑 | 谁先谁后、什么条件下回退、最多跑几轮，均由流水线在构造时确定，不交给模型临场决定 |
| 统一事件出口 | 内部所有智能体产生的事件从同一个 `reply_stream` 流出，调用方无需知道其中有几个智能体 |
| 处理人机交互 | 任一智能体停在工具授权上时，流水线结束事件流而非挂起；恢复时把答复送回被挂起的那一个 |

第三件是流水线存在的主要理由。多个智能体轮流工作时，「当前是谁在等待人的答复」是一份必须维护的状态：交给调用方，则每换一种编排方式都要重写一遍。流水线把它收在内部 —— 中断时事件流直接结束，进度留在各智能体自己的 `state` 里；恢复时依据事件自带的 `reply_id` 判断当时是哪一方被挂起，因此**没有任何一方需要额外记录「刚才轮到我」**。

## 统一的对外形态

`PipelineProtocol` 描述的就是「接收输入、流式产出事件」这一件事：

```python
class PipelineProtocol(Protocol):
    def reply_stream(
        self,
        inputs: Msg
        | list[Msg]
        | UserConfirmResultEvent
        | UserInterruptEvent
        | ExternalExecutionResultEvent,
    ) -> AsyncGenerator[AgentEvent | Msg, None]:
        """回复输入，并流式产出过程中的事件。"""
```

`Agent` 天然满足它 —— 一个智能体本身就是「只有一个成员」的流水线。因此凡是接受智能体的地方，流水线也能进去：

```python
async def watch(target: Agent | PipelineProtocol, inputs) -> None:
    async for event in target.reply_stream(inputs):
        print(event)
```

[终端 UI](/versions/2.0.8dev/zh/building-blocks/console) 的 `launch_console` 就是这样放宽的，可以直接把流水线丢进去调试。
