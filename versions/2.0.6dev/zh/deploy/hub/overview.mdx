在 [智能体服务](/versions/2.0.6dev/zh/deploy/agent-service) 中注册一个 Hub，前端就会多出一个可搜索的应用市场：用户找到需要的 MCP 服务或技能，点几下装好，再装配给自己的智能体。开发者无需自己维护目录，新增一个来源也只是 `create_app` 中的一个参数。

## 工作方式

安装与装配是两个独立的步骤，因此用户只需配置一次，之后处处可用：

<Steps>
  <Step title="安装到自己的资源池">
    用户浏览 Hub 并安装 MCP 服务或技能，填写的凭证一并保存下来。所有 Hub 汇入同一个资源池，装完之后就不必再关心它来自哪个来源。
  </Step>
  <Step title="装配给智能体的工作区">
    在会话中，用户从资源池里挑选，把它加入该智能体的 [工作区](/versions/2.0.6dev/zh/deploy/workspace-manager)，其工具随即对智能体可见。
  </Step>
</Steps>

资源池属于用户，而不属于某一次会话。同一个 MCP 服务可以装配到十个不同的工作区而无需重复填写密钥，也不会随任何一次会话结束而消失。

<Tip>
Hub 是可选的。即使一个都不注册，用户依然可以通过粘贴配置来添加 MCP 服务，通过上传文件夹来添加技能。
</Tip>

## 启用 Hub

按资源类型，把 Hub 分别传给 `create_app` 的两个参数，路由与市场页面会随之启用：

```python 同时注册两类 Hub
from agentscope.app import create_app
from agentscope.app.hub import ClawSkillHub, GitHubMCPHub

app = create_app(
    # ...已有代码...
    # 每个 Hub 在前端对应一个可浏览的目录。
    mcp_hubs=[GitHubMCPHub()],
    skill_hubs=[ClawSkillHub()],
)
```

每个 Hub 都带有一个 `hub_id`，它同时用于接口路径和前端 URL，因此重启前后必须保持不变。同一类型的两个 Hub 不能共用一个 `hub_id`。

## Hub 不可用时

Hub 是远端服务，可能变慢、触发限流、下线，或者被开发者从 `create_app` 中移除。这些情况下服务都会平稳降级：

| 场景 | 用户看到的表现 |
|------|----------------|
| 浏览一个不可达的 Hub | 目录区域显示错误信息，页面其余部分照常可用 |
| 批量装配时其中一项失败 | 失败项连同原因单独列出，其余各项照常装配成功 |
